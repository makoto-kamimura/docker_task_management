# docs

仕様書の本体はリポジトリ直下の [readme.md](../readme.md)。`docs/` には、それ以外の資料を種類ごとのフォルダに分けて置く。

| フォルダ | 置くもの | 書く人 |
|---|---|---|
| [design/](design/) | 設計・計画の資料（仕様書に反映する前の調査や提案、実装計画など）。合意したものから readme に反映する | 人 |
| [runbooks/](runbooks/) | 運用手順書（作業ごと・アラートごと） | 人 |
| [incidents/](incidents/) | 障害のふりかえり（`YYYY-MM-DD-<概要>.md`） | 人 |
| [automation/](automation/) | 不具合・要望の仕分けや実装を自動で回すときの手順 | 人（エージェントに変えさせない） |
| [tasks/](tasks/) | タスク（[タスク一覧](tasks/task.md)。Phase ごとの分解と進み具合） | 人・エージェント |

- 仕様（機能・画面・データモデル・API・決定事項）は readme に書く。`docs/` に仕様の写しを置かない。
- まだ中身のないフォルダには、フォルダを git に残すための `.gitkeep` を置いている。中身ができても消さなくてよい。
- タスクは `tasks/` にだけ置く。設計・運用の資料と混ぜない。
